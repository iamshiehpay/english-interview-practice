# Issue 0041: path to a trustworthy scoring release

## What the saved evidence rules out

The [current mismatch map](0041-rating-mismatch-map.md) shows 40/60 official contract-3.3 outputs failing the frozen pre-feedback label comparison. Structure accounts for 27 misses, 26 below the approved range; ten of twenty cases fail on all three repeats. Recomputing a hypothetical median score from the three saved repeats (without changing any output or release result) yields only **9/20** cases whose four median levels all match their approved ranges. Repetition or majority voting alone cannot resolve this systematic boundary difference. Fixed-input 3.4/3.5 diagnostics also show that switching models or appending prompt clarifications moves misses among dimensions rather than reliably clearing the gate. The 3.5 cases were reused during prompt drafting, so further tuning on them is not independent validation.

The product's [domain definition](../../CONTEXT.md) and [ADR 0006](../adr/0006-use-a-fixed-evidence-based-feedback-contract.md) require four separate, transcript-grounded ratings. [ADR 0016](../adr/0016-use-bilingual-feedback-with-shared-evidence.md) requires paired explanations with one shared set of levels and original quotes. [ADR 0020](../adr/0020-validate-v1-with-ai-persona-loops.md) permits independently reviewed AI labels for v1.0.0 while keeping deterministic constraints. Removing a rating, changing saved outputs, retrospectively changing labels, or widening the existing gate would not be a valid fix.

## Prospective repair, with stop points

1. **Adjudicate the rubric before new feedback.** Build a blind boundary packet from existing question/transcript text, especially the 27 structure misses. Independent raters first score organization without seeing the model level or prior approved level; compare their reasons only after those judgments are frozen. Record where the written 3-versus-4 structure rule is clear and where independent raters genuinely disagree. This is diagnosis; historical labels and release results remain immutable. If raters cannot apply a consistent boundary, stop before spending on another app evaluation and resolve the rubric as a separate product decision.
2. **Make a versioned scoring design that exposes its evidence.** For each dimension, require observable, concise decision fields before selecting a level: which requested parts were substantively answered; which quoted action/reason has a defensible consequence; which *transcript-internal* statements are connected causally, contrastively or stepwise; and which exact wording causes an English-expression issue. A missing result or another unanswered requested part must not silently lower structure. Use a fixed mapping from these fields to levels where the rubric actually permits one. Keep the original transcript quotes and one shared set of ratings; produce English and Traditional-Chinese explanations from that same assessment. This is a prospective new contract, not post-processing of saved outputs to force a pass.
3. **Verify the design on new blind cases.** Freeze fresh questions/transcripts and independent AI Role-persona approvals before generating any new feedback. Use targeted tests for field/schema/quote integrity and dimensional separation, then a separately capped small diagnostic with independent bilingual review. Do not reuse the eight 3.4/3.5 development cases as a claimed held-out result. If the diagnostic fails, preserve the evidence and stop rather than relabel or rerun the failed cases.
4. **Run the unchanged official release gate only after a promising blind diagnostic.** A separately approved app evaluation must produce its own frozen analysis/label packet, sixty feedback outputs, automatic and stability checks, independent bilingual semantic review, and required AI-persona validation for changed production behavior. The 3.3 `BLOCKED` report remains the release decision until a new versioned report passes every applicable gate.

The first stop point has now been completed under a separate three-reviewer approval. The [blind structure-boundary handoff](0041-structure-boundary-review-handoff.md) finds both recurring model under-scoring and reproducible disagreement with five historical single-level structure approvals. This supports a **prospective** structure decision rule and a new blind packet; it does not justify changing old labels or starting a full release run now.

This design is a hypothesis, not a guarantee of 60/60 exact agreement. Semantic scoring retains judgment, and even a passing finite run would not prove zero future errors. Its value is that failures become attributable to a named evidence decision or a genuinely ambiguous rubric boundary rather than another unstructured prompt tweak. No model request or production behavior change is authorized by this document; any additional independent AI review or new subscription feedback needs a separate concrete cap and user approval.
