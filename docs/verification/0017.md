# Issue 0017 verification — answer by voice in every answer path

Date: 2026-09-21. Implementation by the main agent.

| AC | Evidence |
|---|---|
| A revision can be recorded, attached to the second attempt | `test/voice-paths.test.js` submits a spoken revision and asserts `attempts[1].recordingId` differs from the first |
| Each Follow-up Question can be recorded, attached to that follow-up's attempt | New `POST /records/:id/follow-ups/:fid/transcription`; the test asserts the attempt carries the recording and the registry entry carries `followUpId` |
| A Focus Point Continuation can be recorded | The continuation is an ordinary Practice Record, so it inherits the primary path; asserted end to end including playback |
| A follow-up transcript is saved as a draft and survives a reload | The draft lives on the follow-up node; the test re-reads the record and asserts the draft, and the browser reloads the value into the answer box |
| A follow-up recording never lands on the primary attempt and vice versa | Asserted at the API (`transcriptDraft` stays off the record, recording ids differ) and in the browser smoke |
| Two follow-ups keep separate recordings | Four distinct recordings across primary, revision and two follow-ups |
| Every recording is replayable, including follow-ups | `playerHtml` is rendered for the current follow-up answer and for the previous follow-up inside the history panel; playback bytes asserted |
| Typing remains available everywhere | Submitting text for a follow-up stores `inputMode: 'text'` with no recording |
| Per-path preconditions still hold | A completed practice, a follow-up that already has an answer, and an unknown follow-up are each refused; the two-attempt limit is unchanged |
| A failure leaves that path's state byte-identical | A failing follow-up transcription returns 502 and the whole record compares equal before and after |
| Deleting the practice deletes primary, revision and follow-up recordings together | Asserted after a four-recording practice is deleted |
| Superseded and abandoned follow-up recordings are dropped | A second follow-up recording supersedes the first; submitting text abandons the pending one; completion discards an unsubmitted follow-up recording |

Follow-up transcription runs through the long-running operations tracker as
`follow-up-transcription`, so it is cancellable, retryable and idempotent per
request identifier like every other provider call, with its own replay path.

Automated evidence: `node --test test/voice-paths.test.js` — 7/7 pass.
`npm test` — 134/134 pass. `npm run test:browser` — PASS, including recording a
follow-up answer with a synthetic microphone and asserting the recording did not
land on the primary attempt.

Limits and what is **not** verified:

- Same synthetic-microphone and demonstration-transcript limits as issues 0015
  and 0016: the workflow is proven, transcription quality is not.
- The follow-up answer box has no autosaving text draft of its own. A typed
  follow-up answer is still lost on reload; only the transcript draft the server
  holds survives. This matches the pre-existing behaviour and was not in scope.
- Real-microphone acceptance across the four answer paths is pending human
  validation.
