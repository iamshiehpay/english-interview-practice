# Issue 0016 verification — retain and replay Answer Recordings

Date: 2026-09-21. Implements [ADR 0019](../adr/0019-retain-local-answer-recordings-for-playback.md).
Implementation by the main agent; an independent read-only reviewer checked the
diff against the acceptance criteria, ADR 0019 and the PRD.

| AC | Evidence |
|---|---|
| A submitted spoken answer keeps its recording, attached to that answer version | `test/recordings.test.js` asserts the attempt carries `recordingId`, the registry entry is `retained` and carries `attemptId` |
| No audio bytes in the database | Recordings are files under `<workspace>/recordings/`; the test reads `workspace.json` and asserts the uploaded base64 does not appear |
| Replay from the Practice Record and the answer-version history | `playerHtml` renders a player beside the feedback and inside `#attempt-detail`; the browser smoke fetches the player's `src` and checks the media type |
| A revision's recording is separate from the first attempt's | Two spoken submissions produce two distinct ids and two files; each plays back its own bytes |
| An edited transcript leaves the bytes unchanged and is labelled | `transcriptEdited` is set from the draft/submitted comparison; the test asserts the played bytes equal the original upload; the player shows 「錄音保留你當時說的原音」 |
| Typed answers and older records open normally with no player | `playerHtml` returns nothing without a `recordingId`; the typed-answer test asserts no recording is written |
| Deleting the record, the job and the workspace delete the recordings | One test walks all three, asserting an empty recordings directory, an empty registry and a 404 on playback; a repeated record delete returns 404 safely |
| Unsubmitted recordings are gone after a restart | The restart test opens a second application over the same directory and asserts only the retained file survives |
| An unreferenced file is swept at startup | The same test writes `orphan-file.webm` directly and asserts it is removed |
| No reference without a file | Files are unlinked only after the transaction dropping the reference commits (`commitThenDelete`); a transcription that fails to commit removes its own file |
| Playback returns the original bytes and media type, refuses cross-origin and missing files | Asserted for content type, `Cache-Control: no-store`, an unknown id, a traversal attempt (`../workspace.json`), an `Origin` header from another site, and a reference whose file was deleted |
| Settings shows the approximate local size | `recordingBytesLabel()` sums retained entries; the browser smoke asserts the settings panel states it |
| Nothing is uploaded | The only outbound audio remains the transcription request; no new outbound path exists |

Automated evidence: `node --test test/recordings.test.js` — 9/9 pass.
`npm test` — 127/127 pass. `npm run test:browser` — PASS, including submitting a
recorded answer, replaying it from the record and the version history, seeing the
local size in settings, and confirming that deleting the practice makes the
recording unplayable.

`test/speech.test.js` was updated rather than deleted: the assertion that the
audio file is removed after transcription now asserts the ADR 0019 rule instead —
the recording is held as `pending`, the legacy temporary directory stays empty,
and the bytes never enter the database.

Limits and what is **not** verified:

- The synthetic recorder produces a fixed 2 KB blob and the demonstration speech
  provider returns a fixed sentence, so nothing here is evidence about capture
  quality or transcription accuracy.
- Playback is asserted by fetching the stream and checking headers and bytes;
  actual audible playback through the browser's audio stack is unverified.
- Disk-full, permission-denied and partially-written-file conditions are not
  simulated.
- Follow-up answers still have no recording of their own; that is issue 0017.
- Retention is uncapped: there is no per-workspace quota or automatic pruning of
  old recordings. The settings panel discloses the size, and deletion is the
  learner's control. A quota was not requested and is not implemented.
