# 五次文字練習驗收

目前本機入口：http://127.0.0.1:4310 。重啟時在專案目錄執行 `npm run start:codex`。

開啟 **設定**，點 **重新檢查狀態** 確認 ready。文字生成與回饋使用你的 ChatGPT 訂閱額度；此輪請使用文字回答。未配置實際語音時不顯示錄音入口。

你已接受 Codex 的本機暫存：請求期間可能把完整文字寫入私人暫存目錄，結束後驗證刪除。強制終止或檔案系統錯誤可能留下資料；後續請求只清理能確認已停止的程序目錄，未知或仍在執行的程序會阻擋清理。憑證另外留在 `.coach-codex`，不會隨練習資料刪除。

## 操作

每次依序：選用履歷或只用 JD → **儲存職缺並產生題目** → 選題 → 自己回答 → 取得回饋 → 選擇自己再試或看英文示範 → **結束並保存**。再次作答非必要，但建議至少一次實際測試修改與比較；AI 生成的示範不算自行回答。不要使用自動測試答案替代親自練習。

以下只是涵蓋範圍建議，可自由更換題目：

| 次數 | JD | 題型 | 要觀察的事項 |
|---|---|---|---|
| 1 | A | role-fit | 第一版與修訂版的回饋是否都有精確引文 |
| 2 | A | technical-communication | 沒做過的能力請坦白說明，以假設方案作答，作為 Experience Gap |
| 3 | B | behavioral | 對照第二份 JD；檢查沒有憑空添加工作要求 |
| 4 | B | experience-depth | 回饋進行中按 Cancel，確認失敗／取消狀態，再用原操作重試並完成 |
| 5 | A 或 B | 自選 | 儲存 Focus Point 後重新整理，確認紀錄仍在 |

至少要有兩份 JD、兩種題型、一個真實 Experience Gap，以及一次親自觀察到的失敗與成功恢復。取消若來不及在操作完成前發生，不算失敗案例；另一次練習再試即可。

## 驗收紀錄

完成後保留各次 Practice Record。依 [evaluation README](../evaluation/README.md#creator-real-use-ledger) 記錄實際 ID、題型、完成時間與失敗結果至 `evaluation/v3/creator-validation.json`。你確認完成與內容真實後，才填入 creator 與 attestedAt。不要把私人回答或登入憑證貼到公開文件。

人工評分是另一項驗收：需先產生與 v3 契約相符的完整實質模型評估案例，再依 evaluation README 的 human labels 規則填寫評分範圍、理由與原文引文；目前的 9 次針對性模型驗證及 fake review packet 不替代完整人工驗收。模型生成的建議不等同人工批准。自動評估、五次親自練習、人工標註必須分開記錄。
