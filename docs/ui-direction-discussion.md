# 下一批規劃：UI 視覺方向改版

日期：2026-09-23。狀態：方向與 mockup 已確認（`design/mockups/workbench-annotated-feedback/`）；尚未產生 PRD／issue。實作排在創作者 5 次驗收練習之後，驗收期間不改 UI。

## 起點

- 使用者表示目前排版「太像 Claude 特有的模板」。
- 2026-09-23 的稽核（fake provider 實際截圖，1440 與 390 寬）確認 8 項典型特徵中符合 6 項：
  - 暖奶油底色：`--mist:#fff4e8`，頁首桃色漸層 `#ffedd5 → #fff4e8`（`public/style.css:17,23`）。
  - 赤陶／桃橘強調色：`--teal:#944427`（變數名是 teal，實際是橘棕）、主按鈕 `#f4a573`（`style.css:8–9,325`）。
  - 單一置中窄欄：內容 780–880px，1440 寬螢幕左右各空約 300px。
  - 28px 大圓角＋柔和暖色陰影卡片（`style.css:113–118`）。
  - 全膠囊按鈕 `border-radius:999px`（`style.css:300`）。
  - 大量留白。
  - 不符合：沒有襯線標題（使用 Avenir Next）。內文灰偏青，屬部分符合。
- 這是刻意選擇的結果：`learner-flow-discussion.md` 記錄 2026-09-18 採用 Headspace 冥想式視覺語言（暖桃／奶油底、珊瑚按鈕、膠囊、24–32px 圓角），恰好與 Claude 產品外觀重疊。本次決策取代該視覺語言。
- 稽核同時發現的資訊架構問題：
  - 練習紀錄的職缺卡片仍把整份 JD 原文當 `<h3>` 標題（2026-09 的截短修正只套用到一處）。
  - 手機回饋頁一次練習約 7300px 高，「結束並保存」在最底。
  - 首頁只有一個輸入框，第一次來的人看不出產品能做什麼。
  - 回饋把學習者原句在多個引文框重複貼出。

## 已確認決策

使用者於 2026-09-23 確認「A 的版面，加上 B 的回饋呈現方式，模擬面試那一頁可以選擇性加入 D 的深色主題」。

- **A. 工作台版面**（參考 Linear、Vercel、Raycast）：中性白／鋅灰表面、單一冷色強調色、6–8px 圓角、細邊框、資訊密度較高；逐字稿使用等寬字。桌面練習頁改為**雙欄**：左為題目與回答，右為回饋。
- **B. 批改式回饋**（參考 Grammarly 編輯器）：逐字稿只呈現一次，回饋引用的句子在原文上標註，評語以旁註呈現並互相連動；四項評分以 1–4 分段條顯示，中文理由可展開；關鍵句修正以行內差異呈現。雙語規則不變：評語用中文，引文是學習者的英文原句、不翻譯。
- **D. 深色面試間**（參考 Yoodli、Final Round AI）：僅套用在「三題短場模擬」頁，以錄音與計時為中心；其他頁面維持淺色。
- 不採用：C. 遊戲化學習風格（Duolingo、Speak），對面試準備與作品集定位過於輕鬆。

## 順序

1. 創作者 5 次驗收練習使用現有 UI 完成（見 `creator-validation.zh-TW.md`）。
2. 靜態 mockup（桌面練習、手機練習、首頁、深色模擬面試、現況對照）已完成，使用者於 2026-09-23 確認方向，存於 `design/mockups/workbench-annotated-feedback/`；設計 token 列在該檔 `:root`。
3. Mockup 確認後，再產生 PRD 與 issue，由實作 subagent 依序執行。

## 待討論問題

- 實作前需決定的取捨（mockup 製作時提出）：
  - 1024–1280px 寬度：回答欄僅約 560px，要提早改為上下堆疊，或把回饋改為可拉出的抽屜。
  - 引文部分重疊：mockup 只合併完全相同的引文；真實模型輸出會部分重疊，需定規則（切段、巢狀標註，或在 prompt 要求引文不重疊）。
  - 逐字稿等寬字體：工程師感強，但約 120 字的閱讀速度比 Inter 慢，需實際試讀。
  - 評分條統一用強調色而非紅黃綠：2/4 不會像不及格，代價是弱項較不醒目。
  - 首頁的靜態回饋預覽：5 秒看懂產品，但回饋版面改動時需同步更新。
- 「練習紀錄把整份 JD 當標題」的 bug 是否先於改版單獨修正。
- 改版後 `docs/verification/` 的瀏覽器驗證截圖需全部重拍。
