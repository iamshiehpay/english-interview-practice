# Contract 3.7 pilot: independent output review

This guide is for **one separately authorized independent AI reviewer after** the sixteen candidate feedback outputs have been saved. The reviewer reads the frozen `pilot-review-packet.json`, not the pilot runner's live process, old 3.3 results or earlier 3.4/3.5 development outputs. They do not alter a model output, approved label, source question, transcript or acceptance criterion. One reviewer evaluates all sixteen outputs against the same two semantic requirements below; automatic validation and label comparison are performed separately by code.

For each output, inspect all six English/Traditional-Chinese coaching pairs (`relevance`, `support`, `structure`, `englishExpression`, strength, priority improvement). Mark bilingual `consistent` only when each pair preserves the same actor, action, certainty, condition, timing (especially completed versus planned), limitation and advice. Exact translated wording is not required, but no counterpart may introduce or omit a substantive claim. If inconsistent, name every affected pair in `contradictoryPairs` using its exact packet pair name and explain the difference.

Also inspect each of the four `decisionEvidence` records against the question, frozen `requestedParts`, transcript and rating. Mark evidence `faithful` only if each relevance `answerQuote` substantively answers its named question part, `relatedQuote` is merely related where used, support's quoted point/detail and reasoning link are defensible and question-related, structure's quoted spans actually have the stated relation and advancement without using missing task content as an organization penalty, and English-expression issues are genuine wording or intelligibility issues rather than factual implausibility or task fit. A mechanically exact substring is insufficient when its claimed meaning is false. If any record misstates the evidence, mark `unfaithful` and list dimension-specific explanations in `evidenceIssues`. The review is independent of whether the numerical rating falls in the frozen label range.

Write `pilot-semantic-review.json` with exactly `{schemaVersion:1,contractVersion:"3.7.0",packetChecksum,reviewerType:"ai",reviewer,reviewedAt,reviews}`. Use the canonical JSON checksum of `pilot-review-packet.json` in `packetChecksum`. Provide exactly sixteen ordered `reviews`, each `{caseId,repeat,outputChecksum,bilingualVerdict,contradictoryPairs,evidenceVerdict,evidenceIssues,rationale}`. Allowed verdicts are `consistent`/`inconsistent` and `faithful`/`unfaithful`; use empty arrays only for passing verdicts. Quote or name the concrete contradiction/evidence gap in the rationale. Do not replace failed output with a corrected answer. A single inconsistent bilingual pair, unfaithful decision record, missing review or failed automatic/rating check makes the pilot **NO_GO**. Even a GO only supports seeking separate approval for a fresh official app evaluation; v1.0.0 remains blocked.
